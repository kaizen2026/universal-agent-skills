Ticket-scoped continuity epochs (#3–#10). The runtime now tracks one revisioned Work-Item Capsule per issue or explicit objective instead of a workspace-wide checkpoint: `activate` binds a harness session to a Work Item ID, `checkpoint --expected-revision <n>` performs a compare-and-swap update under a portable lock and turns a stale contribution into a redacted merge proposal, and `resume` resolves only an explicit Work Item ID or the current session binding. The Codex and Claude Code adapters share one idempotent lifecycle: `PreCompact`/`PostCompact` record one event per native delivery, and `SessionStart` after compaction reconciles and injects the bound capsule within the configured budget (a git HEAD that moved since the last checkpoint is recorded as drift, not treated as failure). Claude's model window and compact-trigger percentage are configured separately and no fallback capacity is invented when the window is unverified. Retention bounds events, checkpoint history, and degraded-hook diagnostics; merge proposals are never auto-pruned. `status` is read-only and reports non-managed hook handlers with remediation guidance. Legacy workspace-wide checkpoints are never adopted automatically: `import-legacy-checkpoint --work-item <id>` is the explicit, provenance-tagged path into a capsule, and `handoff --work-item <id>` exports a capsule as a portable checkpoint document the receiver imports the same way. `cli.mjs` exports `HOOK_CONTRACT` so external delegating wrappers (the claude-agent-skills session-durability plugin) can verify compatibility before delegating.
