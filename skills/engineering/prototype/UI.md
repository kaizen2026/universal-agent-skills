# Visual questions moved to frontend-design

Invoke `/frontend-design` for questions about what a page, component, dashboard, or flow should look like. It retains the useful runnable-variant comparison while adding prerequisite checks, repository and design-system inspection, screenshot evidence, user grilling, and the durable `docs/design/<feature>/DESIGN.md` contract consumed by `/frontend-build`.

Keep `/prototype` for logic and state-model questions. If the visual problem's audience, flows, content, platform, or constraints are unresolved, use `/wayfinder` or `/grilling` before frontend design.
